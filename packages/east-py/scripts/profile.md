## 1. Cython Ordering (`_ordering_cy.pyx`)

**Changes:** Added Cython acceleration for `east/utils/ordering.py`:
- `CyEastKey` cdef class — C-level `tp_richcompare` instead of Python descriptor protocol
- Primitive comparers (`cy_compare_int`, `cy_compare_float`, etc.) as `cpdef` functions using `libc.math`
- Accelerated `compare_for`, `equal_for`, `is_for` factory functions with typed loop variables in closures
- `cy_make_east_key` — returns `CyEastKey`-based key classes for `SortedSet`/`SortedDict`

**Cython extensions active:** `values`, `beast2`, `binary_utils`, `csv`, `ordering`

## 2. Monolithic BEAST2 Decoder (`_beast2_cy.pyx` rewrite)

**Changes:** Complete rewrite of `east/serialization/_beast2_cy.pyx` from closure-per-type factory to monolithic C-level decoder:
- Single recursive `cdef decode_value()` dispatching on type tag via `if/elif`, replacing Python closure dispatch
- `int*` offset parameter modified in place — eliminates `(value, offset)` tuple allocation at every recursion level
- Inline `cdef` binary read functions (`read_varint_fast`, `read_zigzag_fast`, `read_float64_fast`, `read_string_fast`) that advance offset via pointer
- `PyUnicode_DecodeUTF8` for direct UTF-8 decode from buffer pointer — avoids intermediate `bytes()` copy
- `memcpy` for float64 reads — avoids `struct.unpack_from` Python call
- Per-type caches (`_struct_cache`, `_variant_cache`, `_dict_cache`) keyed by `id(type_val)` for field types, interned keys, and case names
- No factory phase — type_ctx stack of type values managed at decode time for Recursive type resolution

**Cython extensions active:** `values`, `beast2`, `binary_utils`, `csv`, `ordering`

**Note:** This change only affects BEAST2 deserialization. Compile and execute phases are unchanged. Compile/execute times below show variance from different measurement conditions (system load, cProfile overhead); they should not be interpreted as regressions or improvements from this change.

**Best deserialization improvements:**
- `dict_struct_keys`: **-98.4%** (0.2749s → 0.0045s) — closure factory overhead was pathological for complex dict types
- `while_loop`: **-80.3%** (0.0233s → 0.0046s) — many small struct/variant decodings
- `dict_lookup_stress`: **-60.3%** (0.6039s → 0.2396s) — largest absolute saving (364ms)
- `string_stress`: **-53.9%** (0.0345s → 0.0159s) — `PyUnicode_DecodeUTF8` avoids intermediate `bytes()` copy
- `complex_sort`: **-50.6%** (0.2901s → 0.1432s) — deep recursion benefits from `cdef` calling convention
- `variant_matching`: **-52.2%** (0.0807s → 0.0386s) — variant case cache eliminates repeated tuple construction

**Regression:** `deep_struct` (+65.1%, +4ms absolute) — deeply nested small structs where per-decode cache lookup (`id()` + `dict.get`) slightly outweighs the eliminated closure overhead. Absolute impact is negligible (4ms).
